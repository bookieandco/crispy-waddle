## Runtime convergence closure

The initial SPORT-AUTO.1-.7 source merge established each bounded subsystem. The runtime-convergence closure stitches them into an automatic, restart-safe loop.

Additional runtime surfaces:

- `packages/director-core/src/live-sports-watcher.ts` — authorized frame -> injected vision provider -> inference-only Director observations. Rights/source checks happen before provider I/O.
- `packages/money-core/src/sports-auto-runtime.ts` — continuous opportunity discovery -> SPORT-PRED prediction engine -> paper/shadow decisions -> official resolution -> sports learning episode -> calibration -> thesis/alpha -> model feedback.
- `packages/money-core/src/postgres-sports-auto-runtime-store.ts` — restart-safe candidate, open paper decision, paper resolution, shadow decision, and shadow resolution state.
- `packages/money-core/migrations/024_sports_auto_runtime_convergence.sql`
- `supabase/migrations/20260929030500_sports_auto_runtime_convergence.sql`

The automatic coordinator remains authority-free:

```
authority = AUTOMATION_COORDINATION_ONLY
canAuthorizeLive = false
canExecute = false
```

The model feedback sink may update model/calibration state for the next prediction, but each feedback receipt is `MODEL_FEEDBACK_ONLY` and cannot mutate wagering limits or create execution authority.

Restart/replay behavior is explicit: persisted candidates and decisions are checked before new paper or shadow decisions are created; resolved candidates are removed from the open set; a second runtime instance sharing the durable store does not duplicate the paper/shadow wager.

The software scheduler deliberately uses injected opportunity, prediction, official-result, and model-feedback providers. This keeps data/provider commissioning separate from runtime correctness and allows each sport to use its own specialist prediction module.
