# JLLM — Build Without Owner MacBook (2026-10-22)

**Status:** source implementation under review; no runtime, device inspection, private deployment or paid host commissioned.

## External blocker — audited device, not a failed device
- GitHub audit queue [#1486](https://github.com/bookieandco/crispy-waddle/issues/1486) covers the owner's M1 MacBook. **`AUDIT_REPAIR_PENDING`** means physical condition and Ollama suitability have NOT been tested. It is not proof of a hardware fault.
- Source registry ID `owner-m1-macbook` remains on an explicit model-serving hold; even a configured endpoint and token must not route inference to it.
- Do not install Ollama, pull model weights, run repairs, request a domain/tunnel, enter payment details or deploy production without separately authorized access/expense/security acceptance.

## Working around the Mac without fabricating a brain
- Default JLLM route stays free/local first. No automatic Anthropic/Gemini API fallback and no paid provider invocation on missing local inference.
- Ask reports `NO VERIFIED MODEL HOST`, opens existing Home / Work / Activity / Memory / System status routes from **canonical** `JHADINA_WORLDS`, and retains opt-in Wikipedia source lookup and current WorkSession/browser-local history when available.
- A workspace link only means UI navigation, not that a dependent provider or live action is operational. Legacy classifier returns a limitation, not a general LLM answer.
- Code and unit tests for visuals, navigation, media previews, approval review, model adapters, repository audit and the service gateway can proceed in GitHub CI with synthetic data.
- No substitute "free GPT-6" is claimed. Actual generative reasoning requires a verified model host. Current browser-local conversation cache is not durable cross-device chat.

## Model-host independent route
- The canonical `IntelligenceRouter` + `CapabilityAwareModelRouter` are retained (no second AI/router). The Ollama transport is host-agnostic; it now requires a stable `JHADINA_LOCAL_MODEL_HOST_ID` for candidate admission.
- `owner-m1-macbook` is blocked pending independent audit and reviewed source release.
- A **different, separately approved** private inference host can be identified with its own ID, HTTPS allowlisted hostname and server-side authentication. Candidate configuration is not a declaration of live uptime, safe privacy or zero infrastructure costs. No host is being purchased or started in this PR.
- The MacBook remains a future optional host, not an architectural dependency. A serverless function itself cannot supply local GPU/RAM just because routing code exists.
- Keep money, memory mutation, deployment, publishing, wallet signing and external side effects in canonical Action Core approval boundaries.

## Acceptance tests
- Holding host ID `owner-m1-macbook` blocks both loopback and HTTPS, despite a URL and token being present.
- Missing/unidentified host ID cannot become an inferred approved local machine.
- Distinct alternate host ID is selectable for **configuration only**, never automatically commissioned or billable.
- Model-status API is owner-verified, reports a non-secret host readiness and links to the public issue without leaking model tokens.
- No-host Ask panel navigates ONLY to declared canonical read-only-friendly workspaces; no code path asserts live general LLM answers or executes tools.
- On real owner hardware audit: separately collect RAM/disk/power/network results, verify Ollama under owner approval, then remove source hold only with a reviewed change and genuine private-device acceptance.
