# MUSIC-LIVE.16–.20: Spotify metadata OAuth, curated podcasts/radio, native Music host, audio focus

Stack: **PR #1195 → #1196 → #1197 → #1198**. Do not merge out of order. This report describes code, not deployed functionality.

## Coding completed in this PR

- **MUSIC-LIVE.16 (Spotify)**: authenticated first-party PKCE login, per-session CSRF/state + user binding, encrypted httpOnly access/refresh cookies, current OAuth token refresh, local disconnect, metadata-only playlist import, Music connection UI. Requires real SPOTIFY_CLIENT_ID, SPOTIFY_REDIRECT_URI and existing JHADINA_OAUTH_ENCRYPTION_KEY; grants **no Spotify raw-stream or download rights**.
- **MUSIC-LIVE.17 (RSS and Atom)**: bounded **subset** importer for XML already obtained through a separately trusted operator feed workflow. Bounded 1 MB input/120 episode limit, rejects DTD/entity declarations, extracts HTTPS audio enclosures, deterministic episode identity, and routes through `admitPublisherMedia` with documented independent rights review. No arbitrary network fetching, feed auto-subscription, credential proxying or generalized XML semantics.
- **MUSIC-LIVE.18 (radio)**: authenticated, rights-reviewed internet radio directory `GET /api/music/radio`. Filters user-owned Music catalog and only sources with valid active grants. No claimed AM/FM hardware.
- **MUSIC-LIVE.19 (iPhone)**: iOS XcodeGen includes JhadinaAudio, and Jhadina's existing native app has a Music tab with explicit ticket-admission interface, controlled playback actions and Apple's system route picker. Not yet connected to the phone's login/token/session API or physically tested. The existing Safety app still owns the actual host; no second separate application invented.
- **MUSIC-LIVE.20 (Music/TV)**: single-window event-based audio-focus arbitration. Actual Music play pauses TV video and TV play pauses Music; does not claim cross-device or across legacy reloads.

## CI, operational dependencies and honest boundaries

- Exact-head GitHub CI (web/core/native/TV) must pass. Fix at the failing line; only certify the commit actually tested.
- PR #1197 had a failure in `Safety Native iOS` tests (`no such module 'JhadinaSafety'`); repaired project module naming on the parent branch. Simulator tests on this new head are needed to verify.
- Spotify OAuth requires a registered Spotify developer application with callback allowlist, consent and current API access; replay exact provider-account lifecycle. Spotify Web API metadata **does not confer audio playback**.
- Required SWLC recovery, `music_playback_checkpoints` migration, auth RLS drill, approved `music-owned` Storage bucket, one owned media file, signed URL renewal replay, and physical iPhone background audio/CarPlay/AirPlay must be separately commissioned.
- RSS authorization/terms still require human/operator evidence; the parser alone does not verify or purchase rights to re-stream or syndicate content.
- New Swift code is a native host scaffold until the client links real logged-in playback tickets and background entitlement/device confirmation.
- Music/TV focus currently only coordinates mounted mini-players within one document; full TV pages and other devices require an audio-session coordinator.
