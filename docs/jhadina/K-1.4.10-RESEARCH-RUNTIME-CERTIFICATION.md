# K-1.4.10 Research Runtime Certification

Status: COMPLETE

## Certified boundary

Research execution now follows:

ResearchIntent -> validated decomposition -> hashed ResearchPlan -> deterministic PolicyDecision
-> canonical approved research.run execution receipt -> active fenced lease -> provider submission
-> authoritative budget/event accounting -> fenced evidence persistence -> evidence verification
-> KnowledgeCandidate -> contradiction/corroboration gate -> KnowledgeObject admission.

A plan, model output, provider output, or candidate never grants authority by itself.

## Production defects found and repaired during certification

1. pgcrypto functions were outside the pinned Research RPC search path. Crypto calls are now schema-qualified and live functions can resolve the extension safely.
2. Lease handoff restarted event sequence numbers. Admission now allocates the next plan-global sequence, preserving append-only event ordering across retries/workers.
3. Evidence persistence was not independently fenced by the active lease. The runtime now uses jhadina_capture_research_evidence_fenced; the legacy capture RPC is not executable by anon, authenticated, or service_role.
4. Runtime accounting no longer trusts provider-reported source/evidence counts. The executor derives evidence count, distinct source count, measured wall-clock, and minimum task cost/risk before committing usage.
5. The pre-existing research-queue test asserted the second evidence slot on a task that began empty. It now checks the evidence actually attached to the completed task.

## Live transactional certification

Synthetic production tests are wrapped in BEGIN/ROLLBACK and leave no rows behind. Verified:
- canonical receipt binding is required before execution admission;
- a second worker cannot claim an active lease;
- forged lease tokens are rejected;
- accepted execution events are append-only and plan-global;
- cumulative query budgets survive lease handoff and stop further work;
- provider evidence can only be persisted with the active lease token;
- evidence starts unverified and is separately verified;
- verified/fresh/authoritative evidence can validate a candidate;
- unresolved contradictions force disputed status and block admission;
- admitted candidates create canonical Knowledge records with evidence lineage;
- synthetic K-1.4.10 rows are absent after rollback.

## Security posture

Research/Knowledge runtime tables are RLS-enabled and direct anon/authenticated access is revoked.
Execution/admission RPCs are service-role only.
The execution receipt guard is not executable by anon/authenticated.
The research source-performance policy table is RLS protected.
The Supabase security advisor no longer reports the two Research-boundary findings fixed in K-1.4.9.

Remaining advisor findings are pre-existing project-wide fail-closed RLS/no-policy tables, two unrelated mutable-search-path functions, and previously documented Opportunity RPC warnings; they are outside K-1.4.10.
