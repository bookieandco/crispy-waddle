## Implemented
- **.36 Atomic operator rights admission** in `packages/music-core/sql/MUSIC-OPERATOR-ADMISSION-REVIEW.sql`: review-only DDL (NOT deployed), RLS-protected audit table, `security invoker` RPC with explicit `REVOKE EXECUTE` from PUBLIC/anon/authenticated and `GRANT EXECUTE` only to service_role. The Postgres transaction creates the authorized source, asset, and audit receipt together. Existing approval/asset conflicts fail instead of overwriting previous rights. A verified owned track must already exist.
- **.37 Operator adapter** `apps/jhadina-web/src/lib/music/music-operator-admission.ts`: no public HTTP route, no automatic service-role creation, explicit gate, independently downloaded exact private audio SHA-256/byte-length comparison, independent reviewer + operator fields, and a single atomic RPC call. Only a properly restricted operator runtime may supply the privileged client. Unit tests prove no premature write and bytes mismatch refusal.
- **.38 Native API** under `/api/music/native/{config,tracks,playback,checkpoint}`. Native Bearer access token is checked by Supabase Auth `getUser(access_token)`, then reused for user-scoped PostgREST and Storage RLS. No user ID from request headers/JSON accepted. Native playback requires a short-lived ticket with expiry; source metadata cannot grant access.
- **.39 Native iPhone login/player**: SwiftUI username/password sign-in directly to pinned Supabase Auth host; refresh token stored in iOS this-device-only Keychain (never UserDefaults), temporary access token held only in memory. The HTTPS web origin must be supplied as the explicit `JHADINA_MUSIC_WEB_BASE_URL` build setting. The auth host is independently pinned via `JHADINA_MUSIC_SUPABASE_HOST` (default canonical SWLC project). Failed/expired tickets stop playback; remote Play asks the native session to renew. Fractional ISO timestamps, Bluetooth/AirPlay route and background audio wiring retained. Never add a service-role key to iOS.
- **.40 Native cross-device resume**: GET/POST position reads/writes scoped by server-verified JWT + RLS, loaded on track selection, saved on pause and ticket renewal, with 24h validation cap. Tests and operator handoff retained.

## Security and operational limitations
- Signed native audio URLs are transient bearer capabilities visible to AVPlayer/OS network stack until expiry; do not print/log them. URL expiry is not instant revocation.
- Login uses Supabase password grant for accounts that support passwords; passwordless/MFA flows need separate native support. The iOS endpoint is intentionally **unconfigured** unless a reviewed HTTPS web origin is embedded at build time.
- This is not proof that a media file is actually licensed, clean or safe: actual independent byte readback and owner-side verification are still prerequisites.
- The operator adapter trusts the **caller-supplied independent reviewer/operator identities**. Real role authentication, signatures, secure service-role provisioning and human release approval must come from an external audited operator process.
- The privileged Postgres function commits atomically only once installed; migration deployment, RLS admission, actual storage upload, live JWT tests, and local iPhone playback are all pending.
- Native session does not implement MFA/SSO, queue shuffle or all iOS interruption/AVPlayer error observers yet. An interrupted/failed playback must not be counted as a successful playback receipt. Production readiness stays false.
- Music's existing signed-owned-asset resolver signs 180-second links. Native renews proactively; physical interruption and long-duration streaming require real tests.
- CI tests prove source contracts, not licensed audio, deployed SQL, iOS code signing, Apple entitlements or recovered SWLC.
