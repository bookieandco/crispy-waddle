## .01 — Capability renewal
- Browser reads signed URL's exp timestamp solely as a scheduling hint; backend HMAC remains authoritative.
- Requests a new exact-owner GET /api/jhadinatv/sources roughly five minutes before expiry.
- Server already rechecks owner, asset membership, territory, evidence fingerprint and casting right. No token persistence.
- Signed HLS manifest/subresources become invalid at expiry; source refresh reloads the browser player. Seamless stream continuity is NOT claimed.

## .02 — Position/state recovery
- Before renewal, store current local playback position and whether media was playing in an in-memory ref.
- On newly loaded metadata, restore only finite VOD time clamped to duration minus one second. Never seek a live channel.
- A URL unchanged within the same issuance second triggers a local reload. Does not create a third-party stream or bypass provider.
- Cast sessions are not silently swapped; reconnect authorization on the receiver separately.

## Follow-on JTV-PLAYBACK.05–.06 — session and receiver lifecycle
- `.05`: each source renewal / route cleanup invokes `UnifiedMediaSession.dispose()`; it removes media-element event listeners, remote polling and state observers, and disconnects the receiver without automatically playing an old local video. Disposal is idempotent and blocks new session commands.
- `.05`: an in-flight transfer that finishes after disposal is disconnected rather than reviving a stale polling session. Media command failure during transfer also disconnects the receiver.
- `.06`: failed Chromecast media loads terminate the newly requested receiver session and keep remote state disconnected, rather than abandoning a connected device.
- Synthetic tests verify cleanup on source replacement, navigation, failed transfer, and receiver media-load failure.
- All existing owner/rights/HLS restrictions remain in place; physical hardware and rights receipts are not established by this work.
