## Gap 1 closed — reusable Performance Master

Added `performance-master.ts`.

Director can now persist an approved performance independently from the character that originally performed it. A Performance Master records its media/skeletal form, FPS, duration, available performance channels and evidence. A retarget plan separately declares the target character and a preservation matrix for motion, timing, camera, lighting, environment, voice and wardrobe.

Canonical rule:

```text
CHARACTER = who performs
PERFORMANCE MASTER = how the performance moves/acts
VOICE = how the character sounds
```

Motion and timing cannot be silently regenerated by a retarget plan. Exact performer-replacement mode also requires source-camera preservation.

## Gap 2 closed — long-form multi-character dialogue state

Added `longform-dialogue-state.ts`.

The existing dialogue coverage system handled camera geometry and per-shot dialogue generation, but did not own persistent multi-segment speaker state. The new state adds:

- canonical character -> voice identity binding;
- ordered dialogue/reaction turns;
- listener ownership;
- segment chains with stable visual anchors;
- continuation packets carrying the previous speaking character and evidence;
- fail-closed voice crossover detection;
- fail-closed segment gaps/reuse/unassigned turns.

This makes a long conversation one governed scene made from many generation segments rather than unrelated short clips.

## Gap 3 closed — 3D mocap normalization and Blender certification

Added `motion-capture-3d.ts` and wired it into the existing Studio `rig` capability.

### Capture modes

- monocular;
- multi-view single person;
- multi-view multi-person;
- Internet/reference video.

Multi-view plans require multiple sources and explicit calibration. Full-body body capture requires full-body and foot visibility. Hand capture cannot claim finger coverage when the source skeleton does not contain finger joints.

### Skeleton compatibility gate

Every source/target skeleton profile explicitly records:

- topology ID;
- joint list and parent graph;
- root joint;
- rest pose;
- forward/up axes;
- rotation representation/order;
- unit scale;
- FPS;
- finger-joint coverage.

Axis, rotation, scale, FPS or rest-pose differences produce a normalization step before Blender.

### Learned retargeting boundary

Learned retargeters are optional specialists, never the canonical motion authority.

A learned retarget profile must be explicitly `production-admitted`, support both source and target topology IDs, and satisfy any rest-pose requirement before Director selects `learned-retarget-then-blender`.

A research-only profile falls back to normalization/native Blender rather than being treated as production-safe.

This decision reflects the reviewed `DeepMotionEditing/deep-motion-editing` issue history: custom skeletons can trigger checkpoint dimension mismatches; custom dataset/skeleton configuration remains brittle; reports exist for jitter, rotation/skinning problems, full-finger questions and platform/path assumptions. The useful ideas remain available without making that repository the production authority.

### EasyMocap placement

`zju3dv/EasyMocap` remains an optional/open-source capture and reconstruction backend. Its useful role is upstream capture/reconstruction: multi-view, multi-person and Internet-video motion reconstruction plus SMPL-family/keypoint outputs. Director normalizes those outputs before retargeting.

### Blender placement

`blender/blender` is the canonical 3D motion certification environment for this architecture.

The reviewed main repository includes official BVH import/export support with axis, scale, FPS and rotation conversion controls, Rigify, NLA infrastructure and IK solving. Director therefore uses Blender for final normalization/retarget cleanup and certification rather than treating an ML retargeter as authoritative.

## Blender certification gate

A mocap-backed Studio rig artifact is rejected unless the worker returns a matching `BlenderMotionCertification`.

Certification checks:

- project/plan/character lineage;
- rest-pose alignment;
- complete bone mapping;
- normalized scale and FPS;
- left/right mapping;
- zero joint flips;
- policy-bounded foot slide;
- policy-bounded ground penetration;
- policy-bounded root drift;
- policy-bounded jitter;
- contact preservation when required;
- export round-trip when required.

Thresholds are project policy, not hard-coded universal constants.

## Studio integration

`RigAnimationInput` now accepts an optional `motionCapturePlan`.

The rig worker receives the plan. When present, the worker must return a Blender certification receipt. The Studio rig provider validates that receipt before returning reusable rig/animation assets or motion evidence.

This preserves the existing Director authority chain:

```text
approved tracking / capture evidence
-> governed rig action
-> optional mocap compatibility route
-> worker
-> Blender certification
-> Studio evidence
-> downstream QC / approval
```

## Targeted certification added

New targeted tests cover:

- Performance Master/retarget preservation;
- multi-character voice and segment continuity;
- 3D mocap routing and research-retarget fallback;
- Blender foot-slide rejection;
- Studio rig rejection when a mocap worker omits Blender certification;
- Studio rig admission when Blender certification passes.

The Director targeted workflow now includes these tests plus the previously existing Studio rig test.

## Final architecture

```text
SCRIPT / STORY / PERFORMANCE INTENT
              |
              +--> Long-form dialogue state
              |      -> speaker / voice / segment continuity
              |
              +--> Performance Master
              |      -> video retarget / performer replacement
              |
REFERENCE VIDEO(S)
              |
              +--> capture provider / EasyMocap-class backend
                       |
                       v
                canonical skeleton profile
                       |
                compatibility / normalization gate
                       |
          optional admitted learned retargeter
                       |
                       v
                    Blender
             rig / IK / NLA / cleanup
                       |
              Blender certification
                       |
                       v
              governed Studio rig asset
                       |
                  Director QC
                       |
                 asset approval
```

The final principle is: external models may capture or propose motion, but Director owns identity, continuity, lineage, compatibility, QC and approval; Blender certifies 3D motion before it becomes production-approved.
