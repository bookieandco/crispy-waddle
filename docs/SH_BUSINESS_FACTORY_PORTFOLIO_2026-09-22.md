## Decision

All side-hustle opportunities from the 2026 research/video audits are folded into the existing Opportunity Core authority.

This does **not** create a second Side Hustle execution engine. Opportunity Core remains the canonical discovery, evidence, scoring, lifecycle, and outcome-learning authority. Owning domains remain responsible for execution.

The rich Side Hustle taxonomy is classification metadata beneath the existing Opportunity Hub categories.

## Canonical operating rule

AI is leverage, not the business.

A Side Hustle opportunity should be promoted because customers already pay to solve the underlying problem and Jhadina can improve one or more of:

- speed;
- cost;
- quality;
- conversion;
- availability;
- personalization;
- repeatability;
- distribution;
- fulfillment.

The preferred lifecycle is:

market observation
-> economic pain
-> buyer
-> evidence
-> assumption attack
-> bounded validation experiment
-> customer
-> human/AI-assisted fulfillment
-> measured outcome
-> reusable workflow
-> automation
-> productization
-> scale or kill

## Portfolio roles

- `standalone`: can support revenue independently.
- `add_on`: is primarily an upsell or monetization layer on another business.
- `capability`: supports Side Hustles but should not be represented as an independent guaranteed-income business.

Examples:

- POD / personalized commerce -> PupsonStuff / Commerce
- dropshipping -> Commerce supplier runtime
- owned/commissioned media -> Media / Growth
- jobs/gigs -> Placement
- trading/investing intelligence -> Money Core
- heir/property research -> OverageOS / Opportunity
- federal subcontracting -> Opportunity / SAM

Classification never grants authority to spend money, contact third parties, publish, place trades, procure products, submit bids, or otherwise execute consequential actions.

Those actions still require the owning subsystem plus Jhadina's existing identity, policy, approval, Action Core, audit, and reconciliation boundaries.

## Side Hustle score

The portfolio adds a Side-Hustle-specific score that supplements rather than replaces the canonical Opportunity score.

Positive factors:

- demand
- pain
- buyer ability to pay
- distribution access
- domain advantage
- margin
- recurrence
- automation potential
- reusable IP
- productization potential
- evidence
- process maturity
- knowledge availability
- adoption feasibility
- ROI observability

Penalty factors:

- time to evidence
- customer acquisition cost
- human attention requirement
- capital risk
- competition
- regulation
- platform dependency
- failure cost
- fulfillment complexity

Every factor is normalized to 0-100.

## Automation maturity

Side Hustles can progress through:

`unvalidated`
-> `human_delivered`
-> `ai_assisted`
-> `workflow_automated`
-> `exception_managed`
-> `autonomous_cell`

Automation should follow validation. Jhadina should not automate an unproven business merely because generation is cheap.

## Opportunity doctrine captured from the audits

- Solve existing paid problems.
- Search for expensive, boring, repetitive work.
- Validate distribution before overbuilding.
- Prefer observable purchase signals over blind outreach.
- Demonstrate the outcome before asking for the sale when economical.
- Favor domains where Jhadina already has an advantage.
- Find the market gap before generating supply.
- Teach/audit before transforming when education provides low-friction workflow access.
- Understand and standardize a business process before automating it.
- Preserve human review where errors are material.
- Track adoption as well as technical success.
- Measure realized ROI against a documented baseline.
- Turn each successful delivery into reusable knowledge, workflow, skill, template, agent, managed service, or vertical product.
- Treat the highest-evidence next experiment as the next action; do not pretend uncertain ideas are permanent winners.
