## .15 — Vault-drain transaction attribution, *not* a fraud conviction

`ops/meme/rug_liquidity_exit_research.py::assess_liquidity_withdrawal` consumes two **canonical WATCHKEEPER dual-public-RPC** aggregate snapshots. The snapshots must describe the same pool/mints and increasing Solana context slots. It binds vault account addresses and DEX program IDs to the older canonical `pool_vault_probe` receipt rather than inventing missing data in the WATCHKEEPER summary.

It measures both reserve changes using exact unsigned integer token atoms. A drop in both vaults is a possible **withdrawal pattern**, not proof of malicious intent; other causes include liquidity migration, normal withdrawals, asset transfer and observation gaps. An optional externally supplied `getTransaction`-shaped response is checked for the original signature, successful meta, intervening transaction slot, direct pool-program instruction, vault address account indices, and exact pre/post token-atom balances. An unverifiable transaction cannot corroborate a withdrawal; even a locally coherent response is **not independently authenticated** on-chain.

Output keeps `rugConfirmed:false`, `lpOwnershipVerified:false`, `withdrawalCauseProven:false`, no permissions, no actor claim.

## .16 — Indicative exit comparison only

`assess_exit_routes` validates an existing, SHA-chained **WATCHKEEPER paired Jupiter** receipt and up to 3 additional caller-supplied public quote records. It checks exact mint, SOL output, token input atoms, quote freshness and distinct claimed source families. Quotes from the same aggregate source are never evidence of independence. A second quoted provider cannot establish executable sellability: a Token-2022 transfer hook, gas, slippage, network condition or account restriction can still block a real trade.

All paths, including `MULTI_PROVIDER_INDICATIVE_EXIT_ONLY`, retain `sellabilityVerified:false`, `simulatedSwapSucceeded:false`, `canEnterPaper:false`, and no trading/signing/broadcast.

## .17 — Conservatively reviewed outcomes

`ops/meme/rug_outcome_cohorts.py::adjudicate_reports` accepts only prespecified case identifiers from a verified local cohort seal and **future** outcome observations. An observed vault-drain candidate is marked `REPORTED_RESERVE_DECLINE_NOT_CONFIRMED_RUG`, not true rug fraud; a fully monitored no-incident window is `MONITORED_WINDOW_NO_INCIDENT_REPORTED_NOT_SAFE`, not a permanently safe token. Missing reports remain pending. Conflicting report kinds become `CONFLICTED_SOURCES_UNKNOWN`. Reported findings need at least two declared source families but names/hashes alone are NOT external authentication.

A forged `externalWitnessVerified:true` flag is rejected rather than believed. No output has a certified positive or negative training label. External review/witness verification and attribution remain future acceptance gates.

## .18 — Full prespecified discovery population

`seal_prospective_universe` reads the existing SHA-chained seven-day experiment ledger and **registers every observed mint** before the fixed seal timestamp. It rejects ledger events occurring after seal, missing/duplicate user-supplied actor groups, short control horizons, unsupported/over-limit populations and tampered SHA heads. Each cohort maintains discovery event identity, first observed pool, mint, enrollment count, source head, and an explicit `eligibleCasesExcluded:0`; it reuses the canonical `rug_native_shadow.seal_control_cohort`.

Actor-group assertions and historic data are only self-reported research observations until independently verified; no arbitrary positive/negative labels are invented. The baseline pilot is limited by real discovery sampling and cannot establish whole-chain coverage. No evidence is auto-promoted to trading or calibrated-model training.
